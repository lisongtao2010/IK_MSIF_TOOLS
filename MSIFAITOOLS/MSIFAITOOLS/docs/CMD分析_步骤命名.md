# 【CMD 分析】步骤命名（沟通用语）

> 适用：MSIFAITOOLS（.NET Framework 4.8，WinForms）
> 步骤名的**唯一代码定义处**：`Services/CmdAnalysisStep.cs`（`CmdAnalysisSteps`）
> 编排实现：`Services/CmdPartAnalysisService.cs`；按钮事件：`Form1.cs`
> （主按钮 `BtnCmdAnalyze_Click` = 一次跑完；子按钮 `BtnCmdStep1_Click` / `BtnCmdStep2_Click` / `BtnCmdStep3_Click` / `BtnCmdStep4_Click` / `BtnCmdStep5_Click` / `BtnCmdStep6_Click` = 只跑一步）
> 功能细节（字段映射 / 判定规则 / 全部日志）：`docs/CMD分析_功能概要.md`

## 1. 这份文档解决什么问题

点一次【CMD 分析】，程序其实埋头做了 **7 件事**（最前面 1 步 + 第 1~6 步），以前在口头和文档里叫「阶段 A / 阶段 A2 / 阶段 B」，
说起来容易混（也看不出先后依赖）。现在给每一步起一个**短名字**，以后沟通直接说名字或代号即可：

- 「最前面（特注品 CSV）没生成」→ 一看就知道是「xlsx 文件名第 5 位是 `Z` → 读部品表 → 写 `特注品.csv`」那条通路；
- 「第 3 步（追加）没生效」→ 一看就知道是 02_要領図_部品機能情報.csv 那条通路；
- 「第 4 步（tz.json）没生效」→ 一看就知道是 `AiAppData\<文件名>\特注品.csv`（兜底 `classify\tz.json`）按「品種 → 分类依据」匹配那条通路；
- 「第 5 步（部品コード）没生效」→ 一看就知道是 `部品マスタ\Tbl_部品マスタ.csv` 的「色」列 / 连续符号那条通路；
- 「第 6 步（使い分け）没生效」→ 一看就知道是 `hiroidashiData` 的 xlsx 第 4 列 / 第 12 列那条通路；
- 日志里每步都有前缀 `【第 N 步 · 名字】`，日志和说法一一对应；
- 每一步都写清了「怎么单独验证」，排查时不用整条链路重跑。

> **按钮**：主按钮【CMD 分析】**一次跑完 7 步**（`S0C → S1 → S2 → S3 → S4 → S5 → S6`）；
> 它下面多了六个**子按钮**，点哪个就只重跑哪一步（单步调试 / 重试用，见第 8 节）。
> 「最前面 · 特注品 CSV 生成」不写数据库，只跟主按钮一起执行（也可以由代码用
> `CmdAnalysisStepKind.SpecialProductCsv` 单独调用）。

> 「参照元」列的值**一律等于该行的「図番」**；「部材名」为空的行写库时统一填 **`その他`**
> （与步骤无关、所有来源通吃，见 `PartBasicInfoRepository.BindInsertParameters`）。
> 想分辨某一行是哪一步写的，看「数据来源」列（`CMD分析・アッセンブリ図` / `CMD分析・要領図` /
> `CMD分析・tz.json` / `AI分析` / `手工追加`）。
> 第 4 步现在读的是 `特注品.csv`，但「数据来源」的**文字仍是 `CMD分析・tz.json`**
> （值沿用旧文字，升级前写进库的行也能在重跑第 4 步时被正确剔除 / 覆盖）。

## 3. 逐步说明

> 每一步都能**单独执行**：点【②  执行】区第二行对应的子按钮即可（主按钮仍是一次跑完 7 步）；
> 也可以用下面的 SQL 直接查库确认某一步有没有写成功。

### 最前面 · 特注品 CSV 生成（`S0C`）

- **做什么**：遍历 PDF 文件夹（`AiAppData` 的上一级）下的 `*.xlsx`（跳过 `~$` 临时文件），
  文件名（去扩展名）第 5 个字符是 `Z`（半角 `Z` / 小写 `z` / 全角 `Ｚ` 都认）= **特注品**；
  读该 xlsx 的部品表（工作表 **`カメラ`**，没有这张表时退回第一张工作表），把
  `品種 / 部品名 / 枠区分 / 部品コード / 員数 / 追加対応特注寸法` 写到 `AiAppData\<文件名>\特注品.csv`。
- **第 6 列「追加対応特注寸法」是给第 4 步用的**：第 4 步**直接读这个 CSV、不再解析 Excel**，
  H / W 上下限与备注「特注寸法：…」就从这一列算（原文照抄，字段内的换行压成空格）。
- **取不到值的列就空着**：部品表没有「員数」列 → 该列整列留空；单元格为空同样留空（不补 0、不猜）。
  「追加対応特注寸法」里写着 `追加不要` / `追加しない` / `追加なし` / `追加無し` 的行
  与第 4 步 tz.json 一样**不写进 CSV**（条数写在日志「提示：」里）；前 5 列全空、只有特注寸法的行也不算部品。
- **输出格式**：UTF-8 with BOM、CRLF，第一行固定 `品種,部品名,枠区分,部品コード,員数,追加対応特注寸法`；
  一条明细都没有时也写只有表头的文件（下游可据此判断「这个特注品确实没有部品」）。
- **不依赖数据库**：放在第 1 步之前，即使一览里没有「アッセンブリ図」也会生成。
- **AI 补足（可选：配置了 AI 接口密钥时）**：对每个特注品文件，再让 AI 读该図番的
  `AiAppData\<文件名>\plu_table.txt`（PDF 图面文字），**分两次调用**：
  1. **先补缺行 / 缺字段** —— Excel 里空着的 `品種 / 部品名 / 枠区分 / 部品コード / 員数`，
     以及图面上有、部品表里没有的部品（作为新行追加）；
  2. **再补特注寸法** —— 「追加対応特注寸法」还空着的行，从图面文字里找出特注尺寸原文
     （`2199 ≦Ｗ` 这种写法，第 4 步据此算 H / W 上下限）。

  **Excel 已有的值一律不动，AI 只填空**；行号对不上 / 重复的行会被丢弃。
  没配 API Key 时这一步完全不联网（与原来一样，只写 Excel 读到的内容）。
  提示语在 `Prompts\SpecialProductAdvisor.Prompt.txt`（exe 目录下运行时可改，
  分 `[system]` / `[user_fields]` / `[user_special]` 三节）。
- **同时补足 `classify\tz.json`**：CSV 写完后，把同样的明细同步进 `classify\tz.json` ——
  同一个 xlsx（`file`）的明细按 `品種 + 部品名 + 部品コード` 对上 → **只补空白字段**；
  对不上的 CSV 行追加成新明细（`sheet = カメラ`、`row = 0`）。其它文件 / 其它顶层键原样保留，
  `tz.json` 不存在时不新建（避免和 CadPartSplitter 抢着写）。
- **会清残留**：生成完会删掉 `AiAppData` 里**没有对应特注品 xlsx 的旧 `特注品.csv`**
  （xlsx 改名 / 删掉 / 不再是特注品时），日志写
  `提示：清掉上次生成、这次没有对应特注品 xlsx 的 特注品.csv N 个` ——
  因为第 4 步是「读出所有 `特注品.csv` 就用」，残留文件会把已经不存在的部品挂进部品基本信息。
  只删这个文件名，其它文件一概不动。
- **日志关键字**：
  `【最前面 · 特注品 CSV 生成】扫描 <PDF 文件夹> 下的 xlsx（文件名第 5 位是 Z = 特注品）→ AiAppData\<文件名>\特注品.csv`
  → `特注品 xlsx N 个 → 特注品.csv M 个（明细 K 行）`；
  AI 补足还会多这几行：`  AI 补足：启用（接口 …，模型 …）` / `  AI 提示语：…`
  （没配密钥时是 `  AI 补足：未配置 API Key，跳过`）、
  每个文件 `  提示：<文件名>：AI 补足 字段 N 个 / 新行 M 条 / 特注寸法 K 条`、
  汇总 `  AI 补足：N 个文件有补充（字段 … / 新行 … / 特注寸法 …），调用 AI M 次`、
  tz 同步 `  提示：tz.json：同步 <文件名>（补字段 N 个 / 追加明细 M 条）`。
- **怎么单独验证**：
  - 看 `AiAppData\<文件名>\特注品.csv` 是否存在、第一行是不是这 6 列；
  - 对照原 xlsx 的 `カメラ` 表行数（减去「追加不要」行）是否一致；
  - 拿非 `Z` 文件名的 xlsx 对照：不应生成任何 `特注品.csv`。

### 第 0 步 · 分解与分类（`S0`，按钮外）

- **做什么**：点【开始分解】时，先调用 CadPartSplitter（`Part_NN.png` / `parts_info.json` / `tables\*.csv` 等），
  再由本工具自己做 xy / table / plu 文本分解，最后读上游写的分类清单 `classify\PdfInfoList.txt`，
  得到每张 PDF 的「图面分类」。只有分类为 **アッセンブリ図** 的 PDF 才会进入后面 6 步。
- **日志关键字**：`PDF 文件夹：` / `待处理 PDF：` / `分类统计：`
- **失败的表现**：第 1 步日志出现 `跳过：找不到 …\01_アッセンブリ図_部品機能情報.csv`
  → 说明这步没勾「先调用 CadPartSplitter」，或该 PDF 的图面分类不是 アッセンブリ図。
- **怎么单独验证**：看 `AiAppData\classify\PdfInfoList.txt` 里该図番的「图面分类」列；
  看 `AiAppData\<図番>\` 下有没有 `01_アッセンブリ図_部品機能情報.csv` / `parts_info.json` / `01_アッセンブリ図_要領図.csv`。

### 第 1 步 · 装配图部品入库（`S1`）

- **做什么**：对每个目标 PDF，定位 `01_アッセンブリ図_部品機能情報.csv`（兼容旧名 `LT_STEP1.csv`），
  按列名映射建行（番号 / 部品名 / 枠区分 / 員数 / 基本寸法 / 切断寸法 / 部品コード），
  再用「番号」到该页 `parts_info.json` 的 `callouts` 里找圈号（`text=4` + `display=④4`），
  取圈号所在零件图的全部 `texts`，**去掉含数字的文字**、**去掉 `XX部` 形式的位置标记**，
  剩下的去重后用 `|` 连接写进「部材名」（例：番号 4 → `縦枠`），
  然后用 `xy.txt` 做坐标校验（`坐标一致` / `坐标不符` / `未校验`），最后整図番「先删后插」入库。
- **特注品（図番 第 5 位是 Z）**：PDF 文件名（図番）的**第 5 个字符是 `Z`**（例 `H310Z10004`）时，
  该 PDF 读到的行在写库前把「特注」列写成 **`特注品`**
  （`CmdSpecialProductRule.MarkSpecialProducts`；第 1 / 2 / 3 步的写库点都套用，已有值的行不覆盖）。
  日志：`  図番 … 的第 5 位是 Z → 记「特注品」N 行（数量 / 切断寸法 保留）`。
- **数量 / 切断寸法**：**写库前统一清空**（`特注` 既不是 `1` 也不是 `特注品` 的行）——
  `CmdPartAnalysisService.ClearQuantityForNonSpecial` → `PartBasicInfo.ClearQuantityUnlessSpecial`，
  所以 CSV 里的「員数 / 切断寸法」不会入库（日志 `「特注」不是 1 / 特注品 的行：数量 / 切断寸法 已清空 N 行`）。
  第 2 / 3 / 4 步的写库点也套用同一规则；第 4 步 tz.json 的行（`特注 = 1`）与
  図番 第 5 位是 Z 的行（`特注品`）不受影响。
- **日志头**：`【第 1 步 · 装配图部品入库】读 01_アッセンブリ図_部品機能情報.csv → 建行 → xy.txt 校验 → 入库（N 个 PDF）`
- **逐行日志**：`[i/N] CMD 分析：<文件名>` → `  提示：…` → `  登录成功：N 条（図番 …）` →
  `  部材名：N 行按「番号 → 圈号 → 零件图 texts」取自 parts_info.json`（一行都没填到时不出这行）
- **部材名**：只有「番号 = 图纸圈号」的行才有值（一行对应全部出现处，取合并值，**这一步不加位置前缀**）；
  第 2 步按圈号拆条时**每条取该处零件图的部材名再加 `右 / 左`（或 `上 / 下`）**，
  第 3 步的行改用 01 要領図 清单的「項目」（`A,M` → `A部`）按同一套规则算并加同一套前缀（见第 3 步），
  第 4 步的行、AI 分析行、手工追加行算不出来 → 写库时统一填 `その他`
  （`PartBasicInfo.MemberNameFallback`）；**部材名为空或已是 `その他` 的行不加位置前缀**
  （不会出现 `右その他`）。
- **代码**：`CmdPartAnalyzer.LocateSources` / `Analyze`；入库 `PartBasicInfoRepository.Save`。
- **怎么单独验证**：把该図番的行按 `数据来源 = 'CMD分析・アッセンブリ図'` 查出来，看行数与日志 `登录成功：N 条` 是否一致
  （`参照元` 现在一律等于「図番」，不能再用它分辨是哪一步写的行）。

### 第 2 步 · 圈号拆分（`S2`）

- **做什么**：只处理**第 1 步写入的行**（`数据来源 = CMD分析・アッセンブリ図`，`CmdCalloutPartSplitter.IsAssemblyRow`）。用行上的「番号」到该页
  `parts_info.json` 的 `callouts` 里找圈号（`text=4` / `display=④4`，两者要自洽）；圈号必须出现在
  **index 不同**的零件图里，且这些零件图的 `texts` 整体互为包含（`A ⊆ B` / `B ⊆ A`），
  才按坐标判排列方向（左右 / 上下）给部品名加「右 / 左」「上 / 下」并拆成多条。
  **部材名也加同一套前缀、且按每条对应的零件图取值**（`縦枠` → `右縦枠` / `左縦枠`）。
- **日志头**：`【第 2 步 · 圈号拆分】按 parts_info.json 的圈号（callouts）把「アッセンブリ図」的部品行按位置分割（K 个図番）`
- **逐行日志**：`  分割：番号 3（④4）在 parts_info.json 中 2 个零件图里出现、左右排列 → 部品名加「右 / 左」（1 行 → 2 条）；部材名 右縦枠 / 左縦枠`
  / `  番号 5（…）… 但无法命名 → 不分割` / `  没有需要按位置分割的部品`
  （部材名算不出来的行后面那段 `；部材名 …` 不出现）
- **部材名**：拆出来的每条取**该条对应零件图**的部材名，再加与部品名相同的位置前缀；
  **部材名为空或已是 `その他` 时不加前缀**（`PartMarkSplitPlan.PrefixedMemberNameAt`）。
- **幂等**：备注里已带 `位置：` 的行不再拆第二次。
- **代码**：`CmdCalloutPartSplitter.Split` / `Clone`；判定 `PartsInfoIndex.ResolveCalloutSplit`、部材名 `PartMarkSplitPlan.PrefixedMemberNameAt`。
- **怎么单独验证**：查该図番里部品名带「右 / 左」「上 / 下」的行；或看备注里是否出现 `位置：④4 右`。

### 第 3 步 · 要領図部品追加（`S3`）

- **做什么**：读装配图的 `01_アッセンブリ図_要領図.csv`（項目 / 要領図漢字 / 図番）→ 对每个要領図図番
  读 `02_要領図_部品機能情報.csv`（品種 / 部品名 / 枠区分 / 部品コード / 員数）→
  「品種命中分类依据」的行 + 「品種为空（共通部品）」的行建行，番号接在该図番已有最大番号之后，
  备注写 `品種：xxx；項目：A,M`（共通部品写 `品種：共通`）→ 与第 1 / 2 步的行合并后整図番覆盖写。
  `部品コード` 为空 / 占位符（`―` `-`）/ 纯数字、但「部品名」是真实部品（如 `ロットＮｏ．ラベル` / `ストライク`）的行
  **也登录**：`部品コード` 留空、备注追加 `；部品コード：なし`；没有部品コード 的行去重时额外带上「区分」

### 第 5 步 · 部品コード正規化（`S5`）

- **做什么**：对每个 アッセンブリ図 図番的每一行，把「部品コード」里**颜色那一段换成 `□`**，
  再把**连着出现的符号压成一个 `□`**。例：`MEACC429` → `MEA□429`、`MEA□□405` → `MEA□405`、
  `MZB○○963` → `MZB□963`、`MZB△△955` → `MZB□955`。
- **颜色怎么认**：用 `部品マスタ\Tbl_部品マスタ.csv`（**不属于 AiAppData**）——
  第 1 列 `部品コード` 与表里的「部品コード」比对（忽略大小写、去空格），
  第 3 列 `材質`（`MEA` / `MZB` …）用来定位，第 4 列 `色`（`CC` / `S` …）就是要换成 `□` 的那一段。
  只换**第一处**，而且**只从「材質」之后开始找** —— 所以 `LAVS639`（材質 `LAVS`、色 `S`）不会被误改，
  部品マスタ 里查不到的部品コード（`MZA674` / `MDQ703` …）原样不动。
- **符号怎么压**：`□ ■ △ ▲ ○ ● ◇ ◆ 〇` 这 9 个符号**连续出现 2 个以上**时压成一个 `□`
  （`□` `■` `△` 混着连着也算）；**单个符号保留原样**（`MZA□968` 不变，不会变成 `MZA968`）。
  这一步不需要查部品マスタ，即使 CSV 找不到也照样压符号（找不到时只记警告）。
- **落库方式**：只 `UPDATE [部品コード]`（`PartBasicInfoRepository.UpdatePartCodes`），
  定位键 = 図番 + 页码 + 番号 + 部品コード，**不建行、不删行**，所以第 1 / 2 / 3 / 4 步写入的内容不受影响。
  **下一步（第 6 步 使い分け）就用这里正規化好的部品コード 去查拾い出し表。**
- **撞键保护**：换完以后如果和同図番 / 同页码 / 同番号 的另一行「部品コード」相同（会违反唯一索引），
  那一行**跳过不写**（保持原样）并记一条警告 `  有 N 行因为和别的行重复没能写入（部品コード 保持原样），请手工确认`。
- **文件位置**（`CmdPartCodeNormalizer.ResolveDataSource`，日志会打印实际用的文件）：

  ③ 从分解输出目录（`<PDF 文件夹>\AiAppData`）逐级向上找 `部品マスタ` 文件夹 →
  ④ 从程序目录逐级向上同样找（开发时就在项目目录里）。文件夹里优先 `Tbl_部品マスタ.csv`，
  没有时用最新的 `Tbl_部品マスタ*.csv`（带日期的导出文件）。找不到只记警告、跳过本步。
- **日志头**：`【第 5 步 · 部品コード正規化】按 部品マスタ\Tbl_部品マスタ.csv 的「色」把部品コード 里的颜色换成 □，再把连续的符号（□□ / 〇〇 / △△ …）压成一个 □（只改部品コード 一列）`

## 8. 分步执行：主按钮 + 6 个子按钮（已实现）

界面上现在有 **1 个主按钮 + 6 个子按钮**，两者走同一套代码，只是传给服务层的「执行范围」不同

要点：

1. **名字只有一处**：子按钮文字在 `Form1` 构造函数里由 `CmdAnalysisSteps.ButtonText(kind)` 设置，
   与日志里的 `【第 N 步 · 名字】` 同源；改名字只改 `Services/CmdAnalysisStep.cs`。
2. **单步入口**：`CmdPartAnalysisService.AnalyzeAndSave(…, CmdAnalysisStepKind stepKind)`；
   原来的 3 参数版本保留（内部转成 `All`），旧调用不受影响。
3. **第 2 / 3 / 4 / 5 / 6 步有前置检查**：数据库里这些図番一行都没有时，只记一条警告
   `数据库中还没有这些図番的部品行，请先执行 第 1 步 · 装配图部品入库。` 并立即返回，不做任何写库。
4. **共用界面流程**：`Form1.cs` 的 `RunCmdAnalysisAsync(CmdAnalysisStepKind)` 负责校验 / 快照 / 后台执行 / 汇总；
   `SetRunning(true)` 期间六个子按钮一起置灰（文字不变）。
5. **单步执行不会冲掉其他步骤的数据**：第 2 步只重写「数据来源 = CMD分析・アッセンブリ図」的行
   （`CmdCalloutPartSplitter.Split` 把非装配行原样带回），第 3 步只重写「来源表格文件 = 02 文件」的行
   （`CollectInstructionParts` 先 `RemoveAll(IsInstructionRow)` 再合并），第 4 步只重写「数据来源 = CMD分析・tz.json」的行
   （`AppendTzParts` 先 `RemoveAll(IsTzRow)` 再合并；现在读的是 特注品.csv，只碰这一步自己写的行）；写库前都把该図番其余行整体提交
   （`参照元` 一律写该行的「図番」、空的 `部材名` 一律写 `その他`）。
   第 5 步只 `UPDATE`「部品コード」一列（`UpdatePartCodes`），改完的值不会再被自己改第二次；
   第 6 步最小心 —— 只 `UPDATE`「使い分け」一列（`UpdateUsageKinds`），不建行、不删行、不覆盖已有值。
   **顺序上第 6 步依赖第 5 步**：单独重跑第 6 步前要先跑第 5 步（否则部品コード 还是 `MEACC429` 写法）。
6. **最前面这一步只写 CSV**：`CmdAnalysisStepKind.SpecialProductCsv`（没有界面按钮）
   只执行 `CmdPartAnalysisService.ExportSpecialProductCsv`（`CmdSpecialProductCsvExporter`），
   不打开数据库、不要求一览里有「アッセンブリ図」；主按钮执行时它排在第 1 步之前，
   并且**日志里显示的是 `最前面 · 特注品 CSV 生成`（不占「第 N 步」编号）**。
