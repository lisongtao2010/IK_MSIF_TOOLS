> 适用：MSIFAITOOLS（.NET Framework 4.8，WinForms）

> `Services/CmdSpecialProductCsvExporter.cs`（最前面：特注品 CSV 生成 + 同步 tz.json）、
> `Services/CmdSpecialProductAiAdvisor.cs`（最前面：特注品 AI 补足）、

## 1. 一句话说明

【CMD 分析】是【AI 分析】之外的第二条入库通路：**不调用 AI**，直接读取 CadPartSplitter 在
【开始分解】时生成的 CSV 部品表，把「アッセンブリ図」的部品明细登录到与【AI 分析】**完全相同的
SQLite 表**（`PartBasicInfoRepository.TableName`）。

登录后还有五步后处理（**第 2 步 圈号拆分** / **第 3 步 要領図部品追加** / **第 4 步 tz.json 部品追加** /
**第 5 步 部品コード正規化** / **第 6 步 使い分け自動設定**，前两步旧称「阶段 A2 / 阶段 B」；
都只针对 `classify\PdfInfoList.txt` 里「图面分类 = アッセンブリ図」的记录）：
**第 2 步 圈号拆分** —— 用部品行的「番号」在 `parts_info.json` 的 `callouts` 里找圈号（`text=4` / `display=④4`），
同一个部品在图上装了多处（不同零件图的 `texts` 互为包含）时，按排列方向给部品名加「右 / 左」「上 / 下」
并拆成多条；**第 3 步 要領図部品追加** —— 把各要領図里「品種与分类依据相符」的部品行、以及**没有品種（所有品種共用）**
的部品行一并挂到该装配图名下（**部品名与「アッセンブリ図」行相同时**：把那条装配图行的「区分」覆盖到要領図行上，
再把装配图行删掉 —— 同一部品只留要領図 这一条，见 `CmdPartAnalysisService.MergeInstructionWithAssembly`）；
**第 4 步 tz.json 部品追加** —— 读**最前面那步生成的 `AiAppData\<文件名>\特注品.csv`**
（Excel 部品表的 CSV 版，**不再解析 Excel**；一个 CSV 都没有时才退回旧的 `classify\tz.json`），
把「品種」与分类依据相符的明细（部品名 / 枠区分 / 部品コード / 特注寸法）也挂到该装配图名下；
**第 5 步 部品コード正規化** —— 用 `部品マスタ\Tbl_部品マスタ.csv` 的「色」把部品コード 里的颜色换成 `□`
（`MEACC429` → `MEA□429`），再把连续出现的符号（`□□` / `〇〇` / `△△` …）压成一个 `□`
（`MEA□□405` → `MEA□405`，单个符号不动；只改「部品コード」这一列）。换完会和同図番 / 同页码 / 同番号 的
另一行**撞键**时，那一行跳过并记警告 —— 这就是**重複チェック**（撞键的行不写，保证「页码 / 番号 / 部品コード」唯一）；
**第 6 步 使い分け自動設定** —— 同一図番内「区分 / 参照元 / 部品コード / H下限 / H上限 / W下限 / W上限」
**全部相同的 2 行以上**，按「部品コード」遍历 `hiroidashiData` 里的 `*.xlsx`，找第 4 列
（部品ｺｰﾄﾞ/形材番号）相同的行，把第 12 列（使い分け）的值**按顺序**填到这些行上（只改这一列）。
这一步**放在第 5 步之后**：部品コード 已经统一成 `MEA□429` 这种写法，和拾い出し表第 4 列一致，查表最准。
第 1 步还会顺便填「部材名」：用「番号」找到圈号所在的零件图，把该零件图的 `texts` 去掉**含数字**的文字、
去掉 **`XX部`** 形式的位置标记，剩下的去重后用 `|` 连接（例：番号 4 → `縦枠`；两图各部材 → `鴨居|上レール`）。
第 3 步的行没有圈号，改用 01 要領図 清单的**「項目」**（`A,M` → `A部`）在 `parts_info.json` 里找同一个标记，
按**同一套过滤规则**取部材名（例：`A部` → `縦枠`、`B部` → `鴨居|上レール`）。
入库方式、校验状态、部品信息画面的显示方式与 AI 分析一致。

## 2. 前置条件与按钮校验（点下去先做的判断）

| 顺序 | 检查内容 | 不满足时的表现 |
| --- | --- | --- |
| 1 | 当前没有任务在跑（`_isRunning`） | 直接返回，不重复启动 |
| 2 | 已执行过【开始分解】，一览（`_classifications`）非空 | 弹窗「请先点击【开始分解】…」 |
| 3 | 分解输出目录 `_lastOutputDir` 存在 | 弹窗「找不到分解输出目录，请先执行【开始分解】」 |
| 4 | 一览中至少有一个「アッセンブリ図」 | 单步执行第 2~6 步时弹窗「【分类结果】中没有「アッセンブリ図」的 PDF」；主按钮**不拦**（最前面的「特注品 CSV 生成」不依赖装配图，服务层打一条「无需分析」后返回，CSV 照常生成） |

通过后：把「アッセンブリ図」行做成**只读快照**（`PdfClassification` 副本，避免后台线程与界面并发），
切到【日志】页，`SetRunning(true)`，用 `Task.Run` 在后台执行 `CmdPartAnalysisService.AnalyzeAndSave`，
界面线程只负责把日志回调刷到日志框。

主按钮与六个子按钮共用同一个方法 `RunCmdAnalysisAsync(CmdAnalysisStepKind)`，
差别只在传进去的 `stepKind`（`All` / `Assembly` / `CalloutSplit` / `YoryoAppend` / `TzAppend` /
`PartCode` / `UsageKind`；`SpecialProductCsv` 没有界面按钮，只供代码单步调用）——
校验、快照、日志、汇总、弹窗完全一样，所以单步执行的输出格式与一次跑完时一致。

## 3. 输入与输出

**输入**（全部由【开始分解】+ CadPartSplitter 产生，本功能只读）

| 文件 | 用途 |
| --- | --- |
| `<PDF 文件夹>\AiAppData\classify\PdfInfoList.txt` | 「図番,ファイル名,図面分類,分類根拠」；决定谁是要分析的 アッセンブリ図，以及「分类依据」原文（品種匹配用） |
| `<根>\<図番>\01_アッセンブリ図_部品機能情報.csv` | 装配图的部品表本体（多页时第 2 页起为 `<図番>_P2\…`）；旧名 `LT_STEP1.csv` 兜底 |
| `<根>\<図番>\xy.txt` | 文字坐标，用于交叉校验部品是否真的出现在图上（不存在则跳过校验） |
| `<根>\<図番>\01_アッセンブリ図_要領図.csv` | 该装配图引用的要領図 清单（項目 / 要領図漢字 / 図番） |
| `<根>\<要領図図番>\02_要領図_部品機能情報.csv` | 要領図 的部品明细（品種 / 部品名 / 枠区分 / 部品コード / 員数）；旧名 `LT_STEP2.csv` 兜底。CadPartSplitter 的文件夹名是 **PDF 文件名**，常带分类名（`H453U10002要領図`），而 01 CSV 的「図番」列只有 `H453U10002`，所以定位时会依次试 `<図番>` → `<図番>_P*` → `<図番>*`（図番后面不是半角字母 / 数字的目录） |
| `<根>\<図番>\parts_info.json` | CadPartSplitter 的零件信息（零件框 + 文字 + 坐标）。`texts[]` 里的「A部 / F部 …」位置标记（第 3 步用）与 `callouts[]` 里的圈号 `text=4` / `display=④4`（第 2 步用）都用来给部品名加「右 / 左」「上 / 下」——只认 `index` 不同、且这些零件图的 `texts` 互为包含的零件图；第 1 步还用 `callouts` 定位圈号所在的零件图、按其 `texts` 生成「部材名」，第 3 步则用 `texts` 里的「A部 / M部 …」标记（由 01 要領図 清单的「項目」得来）定位零件图、按同一套规则生成「部材名」 |
| `<根>\<文件名>\特注品.csv` | 最前面那步生成的**特注品部品表**（品種 / 部品名 / 枠区分 / 部品コード / 員数 / 追加対応特注寸法）：**第 4 步直接读它，不再解析 Excel** |
| `<根>\classify\tz.json` | Excel 部品表转成的 JSON（品種 / 部品名 / 枠区分 / 部品コード / 追加対応特注寸法）：只在**一个 `特注品.csv` 都没有**时由第 4 步兜底使用（日志会提示建议先跑最前面那步）；最前面那步会把 `特注品.csv` 的最终内容**同步进来**（只补空白字段 / 追加明细，其它文件与顶层键不动） |
| `<根>\classify\PdfInfoList.txt` | 分类清单（図番号 / 文件名 / 图面分类 / 分类依据）；第 4 步从这里取「分类依据」与明细的「品種」比对 |
| `部品マスタ\Tbl_部品マスタ.csv` | 部品マスタ（第 5 步用，**不属于 AiAppData**）：第 1 列 = 部品コード、第 2 列 = 部品名、第 3 列 = 材質、第 4 列 = 色。文件夹位置与改写规则见第 4 节「第 5 步」小节 |
| `hiroidashiData\*.xlsx` | 拾い出し表（第 6 步用，**不属于 AiAppData**）：第 4 列 = 部品ｺｰﾄﾞ/形材番号、第 12 列 = 使い分け。文件夹位置与匹配规则见第 4 节「第 6 步」小节 |
| `D:\MSIFDB\MSIF_MemberParts.db` | 部材部品マスタ（【AI 分析】用，**不属于 AiAppData**；SQLite 表 `部材部品`：第 1 列 = 部材名、第 2 列 = 部品名）。给 AI 一份「可以回答的部材名」+「部品名 → 部材名」，用于判断取到的部材名到底是不是部材。数据库位置 / 首次导入见「部材名AI推荐」列说明（原 `部材部品\部材部品.csv` 只在数据库为空时用来导入一次） |

**输出**：第 1~6 步只写 SQLite 部品基本信息表（唯一索引：図番 + ページ + 番号 + 部品コード）。
第 1~6 步**不生成、不修改任何文件**（不写 CSV、不动 `AiAppData` 里的分解结果）。

只有**最前面 · 特注品 CSV 生成**会写文件：对 `<PDF 文件夹>` 下文件名（去扩展名）第 5 位是 `Z` 的 `*.xlsx`，
读它自己的部品表（工作表 `カメラ`，没有这张表时退回第一张工作表），生成
`<PDF 文件夹>\AiAppData\<文件名>\特注品.csv`（UTF-8 with BOM、CRLF）：

```csv
品種,部品名,枠区分,部品コード,員数,追加対応特注寸法
H310,片引戸,枠,MEC1234,2,2199 ≦Ｗ
```

- 列固定这 6 个；表头里找不到的列（例如部品表没有「員数」）**整列留空**，单元格为空也留空（不补 0）；
- **第 6 列「追加対応特注寸法」是原文照抄**（字段内的换行压成空格）：第 4 步读这个 CSV 时据此算
  H / W 上下限、写备注「特注寸法：…」，所以第 4 步**不需要再打开 Excel**；
- 前 5 列全空、只有「追加対応特注寸法」的行不算部品，**不写进 CSV**；
- 表头按列名找，全角 / 半角、空格差异不影响（`部品ｺｰﾄﾞ` 与 `部品コード`、`品 種` 与 `品種` 都认）；
- 「追加対応特注寸法」写着 `追加不要` / `追加しない` / `追加なし` / `追加無し` 的行**不写进 CSV**
  （与第 4 步 tz.json 口径一致），条数写在日志「提示：」里；
- 一条明细都没有时也写只有表头的文件（下游可据此判断「这个特注品确实没有部品」）；
- 生成完会**清掉残留**：`AiAppData` 里没有对应特注品 xlsx 的旧 `特注品.csv` 会被删掉（只删这个文件名），
  因为第 4 步是「读出所有 `特注品.csv` 就用」，残留文件会把已经不存在的部品挂进库；
- 这一步不碰数据库，也不要求 `<PDF 文件夹>` 里一定有 PDF。

**AI 补足（可选：配置了 AI 接口密钥时）**

对每个特注品文件，再让 AI 读该図番的 `AiAppData\<文件名>\plu_table.txt`（PDF 图面文字），
**分两次调用**（提示语 `Prompts\SpecialProductAdvisor.Prompt.txt`，运行时可在 exe 目录下改）：

1. **先补缺行 / 缺字段**：Excel 里空着的 `品種 / 部品名 / 枠区分 / 部品コード / 員数`，
   以及图面上有、部品表里没有的部品（作为新行追加）；
2. **再补特注寸法**：`追加対応特注寸法` 还空着的行，从图面文字里找出特注尺寸原文
   （`2199 ≦Ｗ` 这种写法。第 4 步据此算 H / W 上下限、写备注「特注寸法：…」）。

规则：**Excel 已有的值一律不动，AI 只填空**；AI 给的行号对不上（指向表头 / 超出范围）或与已有行重复
（`品種 + 部品名 + 部品コード`）都丢弃；单元格里的换行压成空格、超长截断 ——
因为第 4 步是**按行**读这个 CSV 的。没有 `plu_table.txt`（该図番的 PDF 还没【开始分解】）时跳过 AI 补足并记提示。
**没配 API Key 时完全不联网**，行为与以前完全一样（只写 Excel 读到的内容）。

**同时补足 `classify\tz.json`**：CSV 写完后，把同样的明细同步进 `classify\tz.json` ——
同一个 xlsx（`file`）的明细按 `品種 + 部品名 + 部品コード` 对上 → 只补空白字段；
对不上的 CSV 行追加成新明细（`sheet = カメラ`、`row = 0`）。其它文件 / 其它顶层键原样保留；
`tz.json` 不存在时不新建（避免和 CadPartSplitter 抢着写）。

**【保存 Excel】**（部品基本信息画面上的按钮，不属于 CMD 分析各步，也不改数据库）导出
`<PDF 文件夹>\AiAppData\output\AssyDwg\a_<図番>.xlsx`（**工作表名固定 `アセンブリ図`**，见
`PartBasicInfoForm.ExportSheetName`；文件里只有这一张表，図番 只体现在文件名上），共 13 列：
部材名 / 部品名 / 区分 / 数量 / 切断寸法 / 部品ｺｰﾄﾞ / 参照元 / H下限 / H上限 / W下限 / W上限 / 使い分け / 特注。
其中 **数量 / 切断寸法 / H下限 / H上限 / W下限 / W上限 这 6 列写成「数字类型」单元格**
（Excel 里可直接排序、求和）；这 6 列里不是数字的值（`3-100`、`2枚` 之类）仍按文本写，内容不丢。
其余列全部按文本写 —— `3-100`、`0012` 这样的写法不会被 Excel 自动转成日期 / 数字。

**「数据来源」列**（`PartSourceKind`，数据库列名同为「数据来源」）：标明每行是哪个功能登录的 ——
第 1 步写 `CMD分析・アッセンブリ図`、第 3 步写 `CMD分析・要領図`、第 4 步写 `CMD分析・tz.json`；
老版本【AI 分析】（用 AI 从 `plu_table.txt` 提取整张部品表）写 `AI分析` —— **该功能已停用**，
现在的【AI 分析】只补「部材名AI推荐」（见下面「部材名AI推荐」列），**不新建行**；
部品基本信息画面上手工追加的行写 `手工追加`。第 2 步只是把第 1 步的行拆条，**沿用原来的取值**。
老数据库（本版本之前建的表）打开时自动
`ALTER TABLE … ADD COLUMN` 补上该列，并按「来源表格文件」把老数据回填一次。

**「参照元」列**（数据库列名 = **参照元**，旧名「来源标识」）：**值 = 该行的「図番」**。
写库时统一由 `PartBasicInfoRepository.BindInsertParameters` 填成「図番」（只有図番为空时才退回原来的来源简称）；
`PartBasicInfo.SourceTag` 在内存里仍然是 要領図 / アッセンブリ図 / tz.json / AI分析 / 手工追加 这些简称，
但**不再写进这一列** —— 想知道这行是哪个功能写的，看「数据来源」列。
老数据库打开时 `PartBasicInfoRepository.NormalizeReferenceColumns` 会把不等于「図番」的旧值一并改成「図番」；
列名由「来源标识」改成「参照元」时只改名（`ALTER TABLE … RENAME COLUMN`），**原有数据保留**（随后同样被对齐成「図番」）。

**「部材名」列**（`PartBasicInfo.MemberName`，数据库列名同为「部材名」）：第 1 步入库时用行上的
**「番号」**到该页 `parts_info.json` 的 `callouts` 里找圈号（`"text": "4"` + `"display": "④4"`，
与第 2 步同一套判定），取该圈号所在零件图（`index`）的**全部 `texts`**：
去掉**含数字**的文字（圈号 / 尺寸 / 図番）、去掉 **`XX部`** 形式的位置标记（`A部` / `M部` / `N部`），
剩下的**去重**后用 `|` 连接。例：`H310U10004` 的番号 4 命中 index 2 / 3 两张零件图，
texts 为 `4 / 9.73 / N部 / A部 / M部 / 縦枠` → 部材名 = `縦枠`；两张图各有不同部材时是 `鴨居|上レール`。
第 2 步按圈号拆条时**部材名也加位置前缀**、且按每条对应的零件图取值（`縦枠` → `右縦枠` / `左縦枠`）；
第 3 步的行没有图纸圈号，改用 01 要領図 清单的**「項目」**
（`A,M` → `A部`）在同一个 `parts_info.json` 的 `texts` 里找这个标记，再按同一套过滤规则算出部材名
（`A部` → `縦枠`、`B部` → `鴨居|上レール`，见「阶段 B」第 5 点），拆分时同样加位置前缀
（`右縦枠` / `左縦枠`）。**部材名为空、或已经是「その他」的行不加位置前缀**（不会出现 `右その他`）。
第 4 步的行、AI 分析行、手工追加行既没有图纸圈号、也没有可用的「項目」，
所以算不出部材名 —— **写库时统一填「その他」**（`PartBasicInfo.MemberNameFallback`，
由 `PartBasicInfoRepository.BindInsertParameters` 套用；老库打开时 `NormalizeReferenceColumns`
把空值也补成「その他」）。同样是后加的列：老库打开时自动补列（`PartBasicInfoRepository.EnsureColumn`），
历史数据这一次只补「その他」，算得出来的部材名仍要重跑一次第 1 / 3 步。

**「部材名AI推荐」列**（`PartBasicInfo.MemberNameAiSuggestion`，数据库列名 = **部材名AI推荐**；
后加的可选列，老库打开时 `PartBasicInfoRepository.EnsureColumn` 自动补上）：
只由【AI 分析】写入，**不覆盖「部材名」**。

- 点【AI 分析】时处理「数据来源 = `CMD分析・アッセンブリ図`」的**全部行** ——
  部材名为空、已经是「その他」、单个部材名（`縦枠`）、多个部材名用 `|` 连起来（`鴨居|上レール`）都要判。
  `|` 说明代码把两个番号的名字都挂到了同一行（例：番号 1 和 3 在图面上挨得很近、
  又落进同一张零件图 → `鴨居|上レール`，代码分不清谁是谁）；
  而图上的文字也可能是**部品名**（`部品セット` / `取説` / `鬼目ナット`），甚至根本没写部材名。
- **参照部材マスタ（SQLite：`D:\MSIFDB\MSIF_MemberParts.db` 的 `部材部品` 表；
  `Services\MemberPartCatalog.cs` + `Services\MemberPartRepository.cs`）**：
  第 1 列 = 部材名（可以回答的部材名，例 `上レール / 上枠 / 右縦枠 / 左縦枠 / 下枠 / その他`）、
  第 2 列 = 部品名（`ｼﾞｮｲﾝﾄ金具` / `取説` / `右縦枠上部ｽﾍﾟｰｻｰ` …）。
  这张表拼成提示词里的 `{{MEMBER_TABLE}}`（每个部材名下挂哪些部品名），
  让 AI ①判断「现在的部材名」是部材还是部品、②图纸上没写部材名时能回答一个部材名、
  ③把图上的部品名换成它所属的部材名（`右縦枠上部ｽﾍﾟｰｻｰ` → `右縦枠`、`取説` → `その他`）。
  同一个部品名挂在多个部材下时（1:N，`MemberPartCatalog.GetMemberNamesForPart`），
  「部材マスタ线索」列会把这些部材名全部列出来（`该行部品名「…」在部材マスタ里属于：上ﾚｰﾙ / 上枠`），
  AI 从里面选 1 个。
  **判定顺序（改提示词时保持这个顺序）**：
  ①该行「部品名」在部材マスタ里**只属于 1 个部材** → 就用这个部材名（图上写的是别的文字也以マスタ为准）；
  ②同一个部品名挂在**多个**部材下（`鬼目ﾅｯﾄ(ﾌﾞﾚｰｷ取付用)` → `上ﾚｰﾙ` / `上枠`）→ 只能从这几个里选 1 个，
  AI 按图上文字 / 位置 / 距离 / 「区分」判断（图上写「鴨居」＝ 三方枠の上枠 → `上枠`）；
  ③哪个部材都不属于（`部品セット` / `取説` / ラベル）→ `その他`；
  ④部品名不在マスタ里时，才用图上的文字。
  数据库位置：① 环境变量 `MSIF_MEMBER_PARTS_DB` → ② App.config 的 `MemberPartDatabasePath` →
  ③ 默认 `D:\MSIFDB\MSIF_MemberParts.db`（D 盘不可用时退回 `<程序目录>\Data\MSIF_MemberParts.db`）。
  **程序启动时**（`Program.Main` → `MemberPartCatalogLoader.LoadFor`）就会检查数据库；
  `部材部品` 表里没有数据时才找 CSV 导入一次（读不到只少一份参考、不中断：【AI 分析】日志会提示）：
  ① 环境变量 `MSIF_MEMBER_PARTS` → ② App.config 的 `MemberPartDataPath` →
  ③ 从分解输出目录逐级向上找 `部材部品` 文件夹 → ④ 从程序目录逐级向上找（开发时在项目目录里）。
  文件夹里优先 `部材部品.csv`，没有时用最新的 `部材部品*.csv`；Shift-JIS / UTF-8 都能读。
  导入完成后只读数据库：以后改数据直接用 SQLite 工具编辑 `部材部品` 表（`id` / `部材名` / `部品名` / `登录时间`），
  要重新导入就清空这张表或删掉数据库文件（下次运行自动重建 + 导入）。
  **部品基本信息画面点【保存】时**，会把这次确定的「部材名 + 部品名」自动登录进这张表
  （`PartBasicInfoForm.SaveParts` → `MemberPartCatalogLoader.RegisterRules` → `MemberPartRepository.MergeRules`）：
  没有的组合追加一行，已有的组合只刷新「登录时间」（不重复登录、不改 `id`、保持原有顺序）；
  **跳过** 部材名 / 部品名 为空、部材名 = 「その他」、部材名里含 `|`（`鴨居|上レール` 这种还没确定）的行。
  所以用户在画面上把部材名改对后一保存，下次【AI 分析】就能用上这条新规则；
  比对按 NFKC 归一化（`NormalizeKey`），表里已有 `上ﾚｰﾙ` 时写 `上レール` 不会重复登录。
  同一个部品名可以挂在多个部材下（1:N），所以**只追加、不删除旧组合**。
  比较时统一做 NFKC 归一化（半角カナ → 全角カナ、全角英数 → 半角）+ 去空白 + 大写，
  所以数据库里写 `上ﾚｰﾙ`、图上写 `上レール` 也能对上。
- 数据来自「来源PDF」列那个 PDF 的分解结果

  ①该番号的圈号坐标（`callouts[].pdf_mm.cx/cy`）、②同一零件图里其它番号的圈号坐标、

  PDF 换过文件夹也能定位），找不到再退回本次分解的输出目录；两处都没有时该页跳过，
  日志提示「可重新执行【开始分解】生成」。

  `Prompts\MemberNameAdvisor.Prompt.txt`，可运行时修改），AI 只输出
  `{"1":"上レール","2":"上枠","5":"その他"}` 这种「番号 → 部材名」的 JSON。
  程序只接受**该番号图上候选里真实存在的文字 / 部材マスタ 的部材名（含「その他」）/ 部材マスタ 的部品名
  （换成它所属的部材名）**，AI 编造的文字一律丢弃并在日志里提示。
- **距离表 + 10% 兜底**（保证同一份数据每次点【AI 分析】结果一致）：程序先把
  「每个待判定番号 → 每个候选部材名」的最近距离算好（`CollectCandidateDistances`，
  只比较同一零件图内的文字），作为表 `{{DISTANCE_TABLE}}` 交给 AI（大模型自己算距离不稳），
  并按「全局距离最小、一处文字只配一个番号」算出建议分配（`BuildDistanceAssignments`）。
  最终取值顺序：①AI 的答案；②AI 没给 → 用建议分配；③只剩一个候选 → 用它；
  ④部材マスタ 能判定的（现在的部材名 是部品名 → 它所属的部材名）→ 用它；⑤都不行 → 跳过。
  另外，若某番号「最近候选」比「次近候选」近 **10% 以上**（`ConfidentGapRatio`）
  而 AI 给的却是别的，按距离定并记日志（提示 AI 与坐标不一致）；
  AI 回答的是部材マスタ 的部材名（图上没印这个字）时没有距离数据，直接采用 AI 的判断。

  **校验状态不再用整行背景表示**（否则会把来源色盖掉），改成只给「校验状态」单元格上色：
  坐标不符 → 红底白字、坐标一致 → 深绿色字、未校验 → 默认。
  「部品コード」单元格的粉红色（按部品名 推定的值）与行背景色互不影响（单元格样式优先于行样式）。
  注：第 3 步要領図 按「項目」（`A部`）拆分出来的行，备注里同样会写 `位置：A部 右`，
  所以也显示淡紫色；重新执行阶段 B 会整张重写要領図 行，旧数据的备注也会补上这个标记。

## 4. 执行流程

### 阶段 A：按图纸登录部品（`CmdPartAnalyzer`）

对每个「アッセンブリ図」PDF 逐页读出 CSV，转成 `PartBasicInfo`：

1. **定位文件**：`<根>\<図番>\`（= 第 1 页）+ `<根>\<図番>_P2\_P3_…\`（按页码数值排序，
   `_P10` 排在 `_P9` 之后）。新名字取不到时自动回落旧名（老分解结果仍可用）。
2. **按列名映射，而不是按列号**（表头是图纸原表头，列序 / 列数不固定，可能带换行）：
   - 番号：`番号`
   - 部品名：`部品名 / 部品名称 / 品名 / 名称`
   - 部品コード：`部品コード / コード`
   - 部品図番：`部品図番 / 部品番号 / 図番 / 品番`
   - 枠区分：`枠区分 / 枠`、員数：`員数 / 数量 / 個数`
   - 基本寸法：`基本寸法 / 寸法`、切断寸法：`切断寸法 / カット寸法`
   先「完全一致」再「包含」匹配；匹配用文本会去掉空格 / 全角空格 / 换行。
3. **清洗**：跳过空行与重复出现的表头行；`番号` 解析不出来时按出现顺序补号；
   同一「页码 + 番号 + 部品コード」只保留一条（「下表参照」展开后完全相同的情况）。
4. **坐标校验**：读 `xy.txt` 建索引（`PartCoordinateVerifier`），逐行核对部品是否在图面文字里，
   结果写入 `PartVerifyStatus`（Passed / Failed），并在日志里输出一致 / 不符的条数。
5. **部材名**：用「番号」到该页 `parts_info.json` 的 `callouts` 里找圈号（`text` + `display` 自洽），
   取该圈号所在零件图的全部 `texts`，去掉含数字的文字、去掉 `XX部` 形式的位置标记，去重后用 `|` 连接，
   写入「部材名」（`PartsInfoIndex.ResolveCalloutMemberName`）。番号不是圈号 / 读不到 json 时留空，
   不影响入库；日志里会多一行 `  部材名：N 行按「番号 → 圈号 → 零件图 texts」取自 parts_info.json`。
   **这一步不加位置前缀**（一行对应全部出现处，值是两个零件图的合并值）；等阶段 A2 拆条时
   再按每条对应的零件图改成 `右縦枠` / `左縦枠`。
6. **入库**：`PartBasicInfoRepository.Save(図番, parts)` —— 该図番原有行先删后插（整张覆盖），
   因此同一份数据重复执行不会翻倍。每行的「数据来源」写 `CMD分析・アッセンブリ図`、
   「参照元」写该行的「図番」（来源分类看「数据来源」）。

### 阶段 A2：按圈号分割部品（`CmdCalloutPartSplitter`）

対象図番来自 `classify\PdfInfoList.txt` 里「图面分类 = アッセンブリ図」的记录（清单读不到时退回一览），
再取该 図番 在部品基本信息表里的行，**只处理「数据来源 = CMD分析・アッセンブリ図」的行**（阶段 A 登录的行）：

1. **找圈号**：用行上的「番号」到该页目录的 `<根>\<図番>\parts_info.json`（第 2 页起 `<図番>_P2\`）里
   找 `callouts[]`，要求 `text`、`display`、`no` **三者自洽** —— 番号 4 必须命中
   `"text": "4"` + `"display": "④4"` + `"no": 4`；`display` 里的圈字符（①…⑳ / ⓪）与数字都要等于圈号，
   对不上视为圈号识别有误，该条 `callouts` 数据不采用。
2. **两条追加规则**（与阶段 B 的「A部」标记同一套，`PartsInfoIndex.BuildSplitPlan` 共用）：
   1. 命中的圈号必须来自 **`index` 不同**的零件图 —— 同一张零件图上出现多次仍算一处；
   2. 这些零件图的**全部 `texts`** 整体必须构成 `A ⊆ B` 或 `B ⊆ A` 的包含关系；
      互不包含（各自都有对方没有的文字）说明是不同零件，**不分割**。
3. **排列方向**：每张零件图取第一处，坐标用 `pdf_mm` 的圆心 `cx / cy`；
   X 方向跨度 ≥ Y 方向跨度 → 左右排列（`右 / 左`），否则上下排列（`上 / 下`），3 处再补「中」。
4. **拆条**：有几处就拆几条 —— 第 1 条沿用原「番号」，其余接在该図番**最大番号 + 1** 之后连续编号；
   部品名加方向前缀（`縦枠上部スペーサー` → `右縦枠上部スペーサー` + `左縦枠上部スペーサー`），
   **部材名用同一套方向前缀、且按该条对应的零件图取值**（`縦枠` → `右縦枠` + `左縦枠`）；
   备注追加 `位置：④4 右`（原备注非空时用 `；` 接在后面），其余字段（部品コード / 部品図番 / 員数 …）原样复制。
5. **「その他」不加前缀**：部材名为空、或已经是 `その他`（= 算不出部材名的行）时**保持原值**，
   不会变成 `右その他` / `左その他`（`PartMarkSplitPlan.PrefixedMemberNameAt`）。
6. **写回**：有分割时 `repository.Save(図番, 全行)` 整张覆盖写（先删后插，所以必须提交全部行）；
   备注里已经带 `位置：` 的行**不再拆第二次**，重复执行不会让前缀叠加。

### 阶段 B：追加要領図 部品（`CmdInstructionPartCollector`）

要領図 部品建行 —— **有品種的按品種命中分类依据**；
**品種为空的行（`02` 是単純部品表 / 普通部品表，整张表也可能没有「品種」列）算「所有品種共用」的部品，一律登录**：

1. 用该装配图的「分类依据」原文（形如 `table_05.csv：H310 １７ラシッサ 片引戸 枠 アッセンブリ図`）
   与 `01_アッセンブリ図_要領図.csv` 里列出的每个要領図 図番 对应。
2. 打开该要領図 的 `02_要領図_部品機能情報.csv`，先收集文件里出现过的全部「品種」（非空），
   并统计「品種为空」的行数；**有品種的**用两份比对判定命中：
   - ① 把分类依据按空白 / 标点切成单词，与品種做**完全一致**比较（全角转半角、去空白、忽略大小写）；
   - ② 一个都没命中时退回**包含**比较（依据里各词可能没有分隔符）。
3. 只对「品種命中 或 品種为空」的行建行，同要領図 内
   「品種 + 部品名 + 部品コード」去重（共通行用固定键 `#共通`，不会吞掉同名同碼的有品種行）。
   **品種为空 ≠ 丢弃**：`02` 由単純部品表 / 普通部品表摊平时没有品種信息（表头甚至没有「品種」列），
   这些行是**所有品種共用**的部品 —— 一律登录，备注写 `品種：共通`；品種格里只写
   `―` / `-` / `／` / `・` / `共通` / `なし` / `無` 这类占位符时同样按共通处理（`IsBlankKind`）。
   （日志：`另有 N 行没有品種（共通部品），一并登录`；品種都不命中时
   `品種（…）都不在分类依据里 → 只登录无品種（共通）的 N 行`）。
   **部品コード 有效性**（`IsValidPartCode`）：去掉空白、全角转半角后应当至少含一个英文字母；
   **空、「―」「-」「／」等占位符、纯数字不会让整行丢弃** ——
   只要「部品名」像真实部品（`IsUsablePartName`：归一化后至少有一个非数字、非占位符号的字符，
   如 `ロットＮｏ．ラベル` / `ストライク`），照常登录，`部品コード` 留空、备注追加 `部品コード：なし`，
   日志 `要領図 <図番>：部品コード 为空 / 无效 N 条 → 按部品名登录（部品コード 留空，备注「部品コード：なし」）`；
   部品名也读不出来（空 / 纯数字）时才丢弃（计入 `InvalidCodeRowCount`，日志
   `要領図 <図番>：部品コード 为空 / 无效、部品名也读不出来 N 条，已跳过`）。
   没有部品コード 的行去重键额外带上「区分」，同名部品（如 `ロットＮｏ．ラベル` 的
   縦枠セット / 上枠セット）会各登录一条。
   若该 `02` 文件没有「部品コード」列，则不做这个校验（退回「部品名或部品コード 非空即可」）。
4. **部品名的位置前缀**（`PartsInfoIndex`）——02 文件里没有「項目」列，項目 来自 01 要領図 清单：
   1. 取項目值的**第一项**并补「部」字：`A,M` → `A` → `A部`（`A` 也是 `A部`）；
   2. 到装配图的 `<根>\<図番>\parts_info.json` 里找文字正好是 `A部` 的记录，按 `pdf_mm` 取**文字框中心**，
      相距 1mm 以内的重复提取先合并成一处；
   3. **分割记录的追加规则**（避免把碰巧同名的标记当成两处而拆错）：
      1. 需找多条数据时，必须对应 **index 不同**的零件图 —— `index` 相同表示同一张零件图，出现多次也只算一处；
      2. 需找多条数据时，这些 index 下的**全部 text**（`texts[].text` 归一化后的集合）整体必须构成
         `A ⊆ B` 或 `B ⊆ A` 的包含关系（两两可比），只有这样的数据才允许分割记录；互不包含说明是不同零件，不分割。
         例：`Part_02` 的文字（`4` / `N部` / `A部` / `縦枠` / `M部` / `9.73`）⊇ `Part_03`（只少 `9.73`）→ 可分割；
         `Part_01`（`鴨居` / `F部` / `上レール` / `B部` …）与 `Part_09`（`Ｖレール` / `ツバ材` …）互不包含 → 不分割。
   4. 满足上面两条后，按不同零件图的代表点（每张零件图取第一处）判断排列方向：
      X 方向跨度 ≥ Y 方向跨度 → **左右排列**，否则**上下排列**；
      再按位置排序给部品名加前缀 —— 左右排列（X 从大到小）`右 / 左`、上下排列（Y 从小到大）`上 / 下`，
      3 处时补「中」（`右 / 中 / 左`、`上 / 中 / 下`）。
      例：`縦枠上部スペーサー` → `右縦枠上部スペーサー` + `左縦枠上部スペーサー`（各占一个番号、員数沿用 02 原值）；
      拆成多条时**每条备注追加 `位置：A部 右`**（与阶段 A2 按圈号分割的 `位置：④4 右` 同一个前缀，
      部品基本信息画面据此把这类行标成**淡紫色**）；
   5. 只有 1 个零件图、零件图之间文字互不包含、`parts_info.json` 不存在（老分解结果）、
      或超过 3 个零件图（无法命名）时**不加前缀**，部品名原样；
      部品名为空时不加前缀。
5. **部材名**（`PartsInfoIndex.ResolveMarkMemberName`）：`02` 文件里没有「項目」列，項目 来自 01 要領図 清单 ——
   与上面第 4 点用**同一个标记**（取第一项补「部」：`A,M` → `A` → `A部`）：
   1. 到装配图的 `<根>\<図番>\parts_info.json` 的 `texts` 里找文字正好是 `A部` 的记录；
   2. 取这些记录所在零件图（`index`）的**全部 `texts`**，按与第 1 步**同一套过滤规则**
      （`PartsInfoIndex.JoinMemberNames`）—— 去掉**含数字**的文字（`4` / `9.73` / 図番）、
      去掉 **`XX部`** 形式的位置标记（`A部` / `M部` / `N部`），剩下的**去重**后用 `|` 连接；
   3. 例：`H310U10004` 的 `A部` 命中 index 2 / 3（texts `4 / 9.73 / N部 / A部 / M部 / 縦枠`）
      → 部材名 = `縦枠`；`B部` 命中的 index 1 → `鴨居|上レール`；
   4. 找不到该标记、`parts_info.json` 不存在（老分解结果）、或过滤后不剩文字时**留空**，
      **写库时统一填「その他」**（`PartBasicInfo.MemberNameFallback`），画面上不会出现空的部材名。
   5. **位置前缀**（与部品名同一套）：标记在 2 处以上且能命名时，每条取**该处零件图**的部材名再加
      `右 / 左`（或 `上 / 下`）—— `縦枠` → `右縦枠` / `左縦枠`；部材名为空或已是「その他」时**不加前缀**
      （`PartMarkSplitPlan.PrefixedMemberNameAt`）。
6. 生成行的规则：

   | 字段 | 取值 |
   | --- | --- |
   | 図番 | アッセンブリ図 的図番（挂在装配图名下） |
   | ページ | 固定 1 |
   | 番号 | 接在已有行最大番号之后连续编号 |
   | 部材名 | 「項目」（`A,M` → `A部`）在 `parts_info.json` 里所在零件图的 texts，去掉数字 / `XX部` 后去重连接（见本节第 5 点）；拆分时按该处零件图取值并加同一套位置前缀（`右縦枠` / `左縦枠`），算不出来 / 「その他」时写库填 `その他` 且不加前缀 |
   | 部品名 / 部品コード | 取自 02 文件（部品名可能带「右 / 左」「上 / 下」位置前缀，见本节第 4 点） |
   | 部品図番 | 要領図 的図番 |
   | 区分 | 取自 02 的枠区分列（単純部品表 / 普通部品表转来的 02 有该列；品種表转来的没有，留空） |
   | 数量 | 取自 02 的員数列（基本寸法 / 切断寸法 留空） |
   | 备注 | `品種：<品種>；項目：<項目>`（項目 来自 01 要領図 清单，多个时 `A / M`；品種为空时写 `品種：共通`）；按位置拆成多条时再追加 `位置：A部 右`；没有部品コード 时追加 `部品コード：なし` |
   | 校验状态 | `PartVerifyStatus.NotChecked`（要領図行不做坐标校验） |
   | 数据来源 | `PartSourceKind.CmdYoryo`（`CMD分析・要領図`） |
   | 参照元 | 写库时统一填该行的「図番」（`PartSourceTag.CmdYoryo` 只留在内存对象上，不写进这一列） |
   | 来源 | `SourceFile` = 02 文件路径，`PdfFile` = 装配图 PDF 路径 |

7. **再次入库**（幂等的关键）：先 `repository.Query(図番)` 取出该図番已有行，
   用 `IsYoryoPartFile`（`02_要領図_部品機能情報.csv` / 旧名 `LT_STEP2.csv`）**剔除上次追加的要領図行**，
   保留阶段 A 的装配图行，再合并本次要領図行后 `Save`（先删后插）。
   → 重复点按钮不会产生重复行，也不会丢掉装配图行。

### 第 4 步 · tz.json 部品追加（`CmdTzPartCollector`，数据源已改为 `特注品.csv`）

**明细从哪来**（步骤名沿用旧名，实际读的是最前面那步生成的 CSV，**不再解析 Excel**）：

1. **优先**：`LoadCsvEntries` 递归读 `<根>\<文件名>\特注品.csv`（列 = 品種 / 部品名 / 枠区分 /
   部品コード / 追加対応特注寸法；表头按列名找，缺列按空），日志统计行是
   `特注品.csv：N 个文件 / M 条明细`；
2. **兜底**：一个 CSV 都没有（例如只单步跑第 4 步、最前面那步没跑）时，退回 `LoadEntries` 读
   `classify\tz.json`，日志警告
   `没有 特注品.csv，改用旧的 classify\tz.json（建议先跑最前面的「特注品 CSV 生成」）`。

之后的规则与以前一样：

1. **対象**：`classify\PdfInfoList.txt` 里「图面分类 = アッセンブリ図」的记录，取其「分类依据」；
   清单里没有该図番时退回一览的 `Evidence`（都没有时日志提示 `没有分类依据…跳过`）。
2. **匹配**（与第 3 步同一套品種比对）：分类依据按空白 / 标点切词，与「品種」做完全一致比较
   （全角转半角、去空白、忽略大小写）；整词一个都不命中时才退回**包含**比较
   （日志 `特注品.csv：品種命中 N 条（命中品種 …，按包含比较命中）`）。
3. **丢弃规则**：`品種` 为空的行跳过（明细没有「共通部品」的概念，日志 `没有品種的明细 N 条`）；
   明细里写着 **`追加不要`**（`追加しない` / `追加なし` / `追加無し` 也算；品種 / 部品名 / 枠区分 /
   部品コード / 追加対応特注寸法 任一处出现即算，忽略全角与空白）→ **整条不追加到部品基本信息**
   （`CmdTzPartCollector.NoNeedMarks`，日志 `明细写着「追加不要」N 条，没有追加到部品基本信息`；
   读 `特注品.csv` 时这种行已经在最前面那步剔掉了，只有退回 tz.json 时才可能再遇到）；
   `部品コード` 必须含英文字母（`IsValidPartCode`，空 / 纯数字跳过）；
   同一 `品種 + 部品名 + 部品コード` 只取一条。
4. **生成行的规则**：

   | 字段 | 取值 |
   | --- | --- |
   | 図番 | アッセンブリ図 的図番（挂在装配图名下） |
   | 页码 | 固定 1 |
   | 番号 | 接在已有行最大番号之后连续编号 |
   | 部品名 / 部品コード / 区分 | 取自明细（`特注品.csv` 或兜底的 tz.json；数量 / 基本寸法 / 切断寸法 / 部品図番 留空） |
   | 特注 | 固定 `1`（`CmdTzPartCollector.SpecialNoteMark`：这些明细都是「追加対応」部品） |
   | H下限 / H上限 / W下限 / W上限 | 由 `追加対応特注寸法`（CSV 第 6 列）自动解析（`ApplySpecialSize`）：`2199 ≦Ｗ` → W下限 `2199` / W上限 `9999`（只写一边时另一边固定 9999・0）；`Ｗ ≦ 2199` → W下限 `0` / W上限 `2199`；`1800 ≦Ｗ ≦ 2000` 两端都取；`＜` 按开区间各让 1；`≦Ｈ` 写进 H下限 / H上限；认不出的写法留空 |
   | 备注 | `品種：<品種>；特注寸法：<追加対応特注寸法>`（没有特注寸法时只写 `品種：…`） |
   | 校验状态 | `PartVerifyStatus.NotChecked`（tz 行不做坐标校验） |
   | 数据来源 | `PartSourceKind.CmdTz`（**值仍是 `CMD分析・tz.json`**：读 CSV 后也没改，见该常量的注释） |
   | 参照元 | 写库时统一填该行的「図番」（`PartSourceTag.CmdTz` 只留在内存对象上，不写进这一列） |
   | 来源 | `SourceFile` = 该行所属的 `AiAppData\<文件名>\特注品.csv` 路径（读 tz.json 时是 `classify\tz.json` 路径），`PdfFile` = 装配图 PDF 路径 |

5. **再次入库**（幂等的关键）：先 `repository.Query(図番)` 取出该図番已有行，
   用 `IsTzRow`（`数据来源 = CMD分析・tz.json`）**剔除上次本步写入的行**，保留第 1 / 2 / 3 步的行，
   再合并本次明细后 `Save`（先删后插）→ 重复点按钮不会产生重复行，也不会冲掉其他步骤的行。
   合并结果为空（该図番原本只有 tz 行、这次一条都不再命中）时改调 `ReplaceByDrawing` 把该図番清空
   ——`Save` 收到空表会直接返回、不清库，所以这一支必须单独处理。

### 第 5 步 · 部品コード正規化（`CmdPartCodeNormalizer`）

目标是把「部品コード」统一成带占位符号 `□` 的写法：**颜色换成 `□`**、**连续符号压成一个 `□`**。
数据源是部品マスタ `部品マスタ\Tbl_部品マスタ.csv`（**不属于 AiAppData**）。
**这一步先跑**，后面的第 6 步 使い分け自動設定 就用这里改写好的部品コード 去查拾い出し表。

1. **対象**：每个 アッセンブリ図 図番，`repository.Query(図番)` 取全部行。
2. **读部品マスタ**：第 1 行是表头（第 1 列 = `部品コード`），按 `部品コード` 建索引（忽略大小写、去空格；
   同一部品コード 重复时只用第一次出现的行，重复条数记一条警告）。只保留三列：
   第 1 列 `部品コード` / 第 3 列 `材質` / 第 4 列 `色`（列号见 `PartCodeColumnIndex` / `MaterialColumnIndex` / `ColorColumnIndex`）。
3. **规则 1 —— 颜色换 `□`**（`Normalize` → `ReplaceColor`）：部品コード 能在部品マスタ 里找到、
   且「色」这一段出现在「材質」之后时，把这一段换成 `□`（`MEACC429`，材質 `MEA`、色 `CC` → `MEA□429`）。
   部品コード 以「材質」开头时**从材質 之后开始找**，所以 `LAVS639`（材質 `LAVS`、色 `S`）里的 `S`
   属于材質、不会被换掉；只换**第一处**；部品マスタ 里查不到的部品コード 原样不动。
4. **规则 2 —— 连续符号压缩**（`CollapseSymbols`）：`□ ■ △ ▲ ○ ● ◇ ◆ 〇` 这 9 个符号
   **连续 2 个以上**（混着连着也算）压成一个 `□`（`MEA□□405` → `MEA□405`、`MZB○○963` → `MZB□963`、
   `MZB△△955` → `MZB□955`）；**单个符号保留原样**（`MZA□968` 不变）。
   这一步不依赖部品マスタ，即使 CSV 找不到也照样压符号。
5. **写库**：只 `UPDATE`「部品コード」一列，定位键 = 図番 + 页码 + 番号 + 部品コード
   （`PartBasicInfoRepository.UpdatePartCodes`）。**不建行、不删行**，第 1 / 2 / 3 / 4 步写入的内容不受影响。
6. **撞键保护**：换完以后若与「同図番 / 同页码 / 同番号」的另一行「部品コード」相同（违反唯一索引），
   这一行跳过不写并记警告 `  有 N 行因为和别的行重复没能写入（部品コード 保持原样），请手工确认`。

**文件位置**（`CmdPartCodeNormalizer.ResolveDataSource`，日志会打印实际使用的文件）：

| 顺序 | 取值 |
| --- | --- |
| 1 | `App.config` 的 `PartMasterDataPath`（文件夹或文件都行，相对路径按程序目录解析） |
| 2 | 环境变量 `MSIF_PARTS_MASTER` |
| 3 | 从分解输出目录（`<PDF 文件夹>\AiAppData`）逐级向上找 `部品マスタ` 文件夹 |
| 4 | 从程序目录逐级向上同样找（最多 16 层，够到盘符根） |

文件夹里优先用 `Tbl_部品マスタ.csv`，没有时用最新的 `Tbl_部品マスタ*.csv`（带日期的导出文件）。

**日志**：

- `【第 5 步 · 部品コード正規化】按 部品マスタ\Tbl_部品マスタ.csv 的「色」把部品コード 里的颜色换成 □，再把连续的符号（□□ / 〇〇 / △△ …）压成一个 □（只改部品コード 一列）`
- `  部品マスタ：<实际使用的文件>` / `  读到部品コード N 件`（有重复时 `  部品マスタ 里有 k 条重复的部品コード（只用第一次出现的行）`）

**已知边界**：

- 颜色只换**第一处**，且只从「材質」之后开始找；部品マスタ 里没有的部品コード（`MZA674` / `MDQ703` …）不改。

### 第 6 步 · 使い分け自動設定（`CmdUsageKindCollector`）

目标是「同一个部品的多行」要把「使い分け」（品種・尺寸区分）填上，
数据源是上游的拾い出し表 `hiroidashiData\*.xlsx`（**不属于 AiAppData**，是拾い出し系统的输入数据）。
**放在第 5 步 部品コード正規化 之后**：这时部品コード 已经统一成 `MEA□429` 这种写法，
和拾い出し表第 4 列的写法一致，查表最准（正規化时撞键被跳过的行保持原样，也能按通配匹配命中）。

1. **対象**：每个 アッセンブリ図 図番，`repository.Query(図番)` 取全部行。
2. **分组**：「区分 / 参照元 / 部品コード / H下限 / H上限 / W下限 / W上限」**7 个字段全相同**
   的行算一组（空值与空值视为相同）；**只有 2 行以上才处理**（单行不是「两条数据都一样」）。
   键的拼法见 `CmdPartAnalysisService.BuildUsageKindGroupKey`。
3. **查拾い出し表**：按组里的「部品コード」遍历 `hiroidashiData` 下的 `*.xlsx`（文件名排序），
   读每张表第一个 sheet 的 **第 4 列（部品ｺｰﾄﾞ/形材番号）**，取相同的行的
   **第 12 列（使い分け）**，按「文件顺序 → 行号顺序」收集（跳过空值）。
   列号 / 表头判定见 `CmdUsageKindCollector.PartCodeColumnIndex` / `UsageKindColumnIndex`。
4. **按顺序赋值**：组内行按「页码 → 番号」排序，第 i 行取收集到的第 i 个值；
   值比行数少时多出来的行**保持原样**（不写空值）；该行**已经有値时不覆盖**（保护手工填的值）。
5. **写库**：只 `UPDATE`「使い分け」一列，定位键 = 図番 + 页码 + 番号 + 部品コード
   （`PartBasicInfoRepository.UpdateUsageKinds`）。**不建行、不删行**，
   所以第 1 / 2 / 3 / 4 / 5 步写入的内容（含第 5 步正規化好的部品コード）不会被冲掉，重复执行也不会累积。

**部品コード 的比对**：第 5 步正規化后的部品コード 与拾い出し表里 `MEA□429` 这种带通配符号的写法，
两边都按通配符比对（`CmdUsageKindCollector.PartCodeMatches`）：
`□ / ■ / △ / ▲ / ○ / ● / ◇ / ◆` 视为任意字符串，其余字符按原样（忽略大小写）比较；
完全一致的部品コード也走同一个判定，直接命中。

**文件夹位置**（`CmdUsageKindCollector.ResolveDirectory`，日志会打印实际使用的目录）：

| 顺序 | 取值 |
| --- | --- |
| 1 | `App.config` 的 `HiroidashiDataPath`（相对路径按程序目录解析） |
| 2 | 环境变量 `MSIF_HIROIDASHI_DATA` |
| 3 | 从分解输出目录（`<PDF 文件夹>\AiAppData`）逐级向上找 `hiroidashiData` 或 `MSIF_InputData\hiroidashiData` |
| 4 | 从程序目录逐级向上同样找（最多 16 层，够到盘符根） |

**日志**：

- `【第 6 步 · 使い分け自動設定】同一図番内…全同的 2 行以上 → 按部品コード查 hiroidashiData 里的 xlsx 第 4 列 → 依次填入第 12 列「使い分け」`
- `  拾い出し表文件夹：<实际使用的目录>` / `  读到 xlsx N 个 / 明细 M 条`
- 每组：`  <図番>：2 行（部品コード MEACC429）← 使い分け 右縦枠上部スペーサー→A / 左縦枠上部スペーサー→A`
- 找不到：`  <図番>：2 行（部品コード MEA□405）在拾い出し表里找不到，跳过`
- 收尾：`  使い分け登录：4 行（図番 H310U10004，命中 2 组）`

**已知边界**：

- 同一个部品コード在拾い出し表里出现多次（不同品種 / 代表ｺｰﾄﾞ）时，只按出现顺序取前 N 个，
  **不按品種对应**（部品基本信息表里没有代表ｺｰﾄﾞ这一列）。

- xlsx 只读第一个 sheet；`.xls`（旧格式）不支持，需要另存为 `.xlsx`。
- Excel 正开着文件也能读（`FileShare.ReadWrite`）；`~$` 临时文件自动跳过。

## 6. 幂等性与容错

- **幂等**：第 1 步按図番整张覆盖写；第 2 步只拆备注里还没有 `位置：` 的行；第 3 步先剔除上次追加行再合并写；
  第 4 步先剔除上次写入的 `数据来源 = CMD分析・tz.json` 行再合并写；第 5 步只 `UPDATE`「部品コード」一列，
  改完的值再跑一次也不会变（第二次执行「正規化 0 行」是正常的）；第 6 步只 `UPDATE`「使い分け」一列、
  且已有值不覆盖（第二次执行写入 0 行是正常的）→ 反复执行结果稳定。
- **缺文件不中断**：缺 01 csv / 01 要領図 清单 / 某个 02 文件时，只记一条提示并累加缺失数，
  其它 PDF 继续。
- **单文件异常隔离**：每个 PDF 的分析包在 try/catch 里，异常计入「失败」并输出错误日志，
  不影响后续 PDF；只有「输出目录不存在 / AI 配置」这类整体性错误才会中断。
- **界面不卡死**：分析在后台线程跑，日志通过回调回到界面；运行期间按钮区被 `SetRunning` 禁用。
- **查看结果**：分析完成后在【分类结果】选中一行 →【部品信息】，即可看到该図番登录的全部明细
  （含第 3 步追加的部品図番 / 備注里的品種）。

## 8. 已知边界（使用注意）

1. **要領図行挂在アッセンブリ図 的図番名下**（`部品図番` = 要領図 図番）。若希望挂到要領図 自己的図番下，
   只需改 `CmdInstructionPartCollector.CollectFromYoryoParts` 里 `assembly.Stem` 一处。
2. 若某张装配图的「分类依据」里**没有任何品種 词**：有品種的行**整张跳过**
   （日志：`品種（…）都不在分类依据里，跳过`）；但该 02 里**没有品種（共通）**的行仍会登录
   （日志：`品種（…）都不在分类依据里 → 只登录无品種（共通）的 N 行`）。
3. 要領図行**不做坐标校验**（`NotChecked`），因此在部品信息画面里不会显示「坐标一致 / 不符」。
4. 旧名兜底只在「新名字文件不存在」时生效：同一个 `<図番>` 目录里新旧两份都在时，用新名字那份。
5. `01_アッセンブリ図_要領図.csv` 的図番列是必需列；缺失时第 3 步直接跳过并提示表头内容。
6. `PartBasicInfoRepository.Save` 传入**空集合时直接返回 0、不执行删除**，所以「本次解析出 0 行」
   （或第 1 步判定无部品数据）时会保留该図番的历史数据，不会把旧记录清空。
7. 「部品コード 必须含英文字母」的过滤**只作用于 02（要領図）**；第 1 步的 01（アッセンブリ図）
   仍按原规则收集全部明细行（如需同样过滤，可在 `CmdPartAnalyzer` 的建行处复用 `IsValidPartCode`）。
8. **位置前缀只改部品名**：拆条后 `部品コード` 不变、「番号」连续递增（唯一索引仍然成立）；
   員数 / 枠区分 沿用 02 文件原值，**不按处数拆分**（2 处不会把員数 1 变成 0.5 / 2）。
9. 「項目」只取**第一项**：`A,M` 只按 `A部` 处理，`M` 不参与
   （如需 `A` / `M` 各自成行，需改 `CmdInstructionPartCollector.BuildItemMark`）。
10. `parts_info.json` 不存在（老分解结果 / 本机没跑 CadPartSplitter）时只是**不加前缀**：
    不提示、不报错，部品名与以前完全一样。位置标记只认**不同 `index` 的零件图**（同一张图里出现多次算一处），
    且这些零件图的全部 `texts` 必须整体构成 `A ⊆ B` / `B ⊆ A` 的包含关系，不满足时同样不加前缀
    （日志会写明 `但零件图（index …）的文字互不包含`）。
11. 「数据来源」「参照元」都是**后加的列**：老数据库第一次被打开时自动补上
    （`PartBasicInfoRepository.EnsureColumn`），并回填一次 ——
    「数据来源」按「来源表格文件」推断（`02_要領図_…` → 要領図、`01_アッセンブリ図_…` → アッセンブリ図、
    `plu_table.txt` → AI 分析），认不出来的（手工录入等）保持空；
    「参照元」**不是来源标识，而是该行的「図番」** —— 每次打开数据库都由
    `NormalizeReferenceColumns` 统一成「図番」（更早的版本里这一列叫「来源标识」、存的是来源简称，
    打开老库时先由 `MigrateLegacyColumn` 改名、数据保留，随后被同一句 UPDATE 覆盖成「図番」）。
12. **第 2 步只认 `parts_info.json` 的 `callouts`**：老分解结果没有 `callouts`、或圈号的
    `text` / `display` / `no` 三者对不上时**不分割**，部品名原样（日志里也不提示，避免噪音）。
    另外 `callouts` 里的 `pdf_mm` 是**圆心** `cx / cy`，不是文字框的 `x / y / w / h`。
13. 拆出来的**第 1 条沿用原「番号」**，其余用「该図番最大番号 + 1」递增 ——
    所以同一部品的多条在部品信息画面里可能分列在番号首尾（不是连续编号）；
    想按部品看全部位置时按 `部品コード` 排序或筛选更直观。
14. 第 2 步的対象来自 `classify\PdfInfoList.txt`（不只看本次一览里的 PDF）：
    清单里列了但这次没分解的図番也会被处理（数据库里有旧行时）。
15. **`02` 里没有品種的行不会被丢弃**：`02` 由単純部品表 / 普通部品表摊平时没有品種列，
    这些行按「所有品種共用」登录（备註 `品種：共通`；品種格里只有 `―` / `-` / `／` / `共通` /
    `なし` 等占位符时同样算共通），日志里与「品種命中」分开计数
    （`品種命中 x 行 + 无品種（共通）y 行`）；同一部品既有品種行又有共通行时各留一条
    （去重键不同：`<品種>#名#码` 与 `#共通#名#码`）。
16. **「部材名」第 1 步用圈号算、第 3 步用「項目」算、第 2 步拆条时按处重算**：第 1 步是
    「番号 → 圈号 → 零件图 texts」，第 3 步是「項目（`A,M` → `A部`）→ 零件图 texts」，
    两者共用同一套过滤规则（`PartsInfoIndex.JoinMemberNames`）。第 4 步的行（`特注品.csv`）、AI 分析行、手工追加行
    既没有图纸圈号、也没有可用的「項目」，算不出部材名，写库时统一填「その他」
    （`PartBasicInfo.MemberNameFallback`），画面上不会出现空的部材名。
    **部材名与部品名加同一套位置前缀**：第 2 步按圈号拆条时、第 3 步按「A部」拆条时，
    每条取**该条对应零件图**的部材名再加 `右 / 左`（或 `上 / 下`）—— `縦枠` → `右縦枠` + `左縦枠`
    （`PartMarkSplitPlan.PrefixedMemberNameAt`，第 1 步单行不拆所以不加）；
    **部材名为空、或已经是「その他」的行不加前缀**（不会出现 `右その他`）。
    过滤规则是「**含数字的文字**整条丢弃」（`9.73`、`1HW2…` 这类尺寸 / 型番不会进部材名）、
    「**以「部」结尾**的文字整条丢弃」（`A部` / `M部` / `N部` 是位置标记）。
    同一张零件图上重复出现的文字只留一条，两张零件图共有同一文字也只留一条。
17. **第 4 步的 特注 / H・W 界限**：`特注` 列对这些明细（`特注品.csv` 或兜底的 tz.json）一律写 `1`
    （`SpecialNoteMark`，代表这行是「追加対応」部品），特注寸法原文只留在备注里；
    `H下限 / H上限 / W下限 / W上限` 由「追加対応特注寸法」（**`特注品.csv` 第 6 列**）
    解析（`ApplySpecialSize`）：只写 `<数字> ≦Ｗ` 时 `W下限 = 数字`、`W上限 = 9999`（固定，`SpecialSizeOpenUpper`）；
    只写 `Ｗ ≦ <数字>` 时 `W下限 = 0`（固定）・`W上限 = 数字`；两端都写则都取，`＜` 按开区间各让 1；
    `Ｈ` 同理写进 H 侧；认不出的写法（没有数字 / 没有 Ｈ・Ｗ）留空。
    明细里写着「追加不要」（`追加しない` / `追加なし` / `追加無し` 也算）**整条不追加**
    —— 读 `特注品.csv` 时这种行已经在最前面那步剔掉了。
18. **第 5 步（部品コード正規化）的边界**：只改「部品コード」一列，不建行 / 不删行；
    颜色只换**第一处**、且只从「材質」之后开始找（`LAVS639` 里的 `S` 属材質，不会被换掉），
    部品マスタ 里没有的部品コード（`MZA674` / `MDQ703` …）原样不动；
    符号压缩只认 `□ ■ △ ▲ ○ ● ◇ ◆ 〇`，**连续 2 个以上**才压成一个 `□`（单个符号保留）；
    换完与同図番 / 同页码 / 同番号 的另一行撞键时该行跳过（记警告，= 重複チェック）；
    部品マスタ CSV 找不到时只记一条警告并跳过本步（不影响其它步骤）。
19. **第 6 步（使い分け）的边界**：只处理「7 个字段全同且 2 行以上」的组，单行不动；
    拾い出し表里同一个部品コード 出现多次（不同品種 / 代表ｺｰﾄﾞ）时**只按出现顺序取前 N 个**，
    不按品種一一对应（部品基本信息表里没有代表ｺｰﾄﾞ列）；已有「使い分け」值不覆盖；
    xlsx 只读第一个 sheet、只支持 `.xlsx`；文件夹找不到时只记一条警告并跳过本步（不影响其它步骤）。
    **必须在第 5 步之后执行**（单独重跑时也要先跑第 5 步），否则部品コード 还是 `MEACC429` 这种写法。
