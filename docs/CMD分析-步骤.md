# 【CMD 分析】按钮执行步骤

入口：`Form1.BtnCmdAnalyze_Click`（`MSIFAITOOLS\Form1.cs`）→ `RunCmdAnalysisAsync(CmdAnalysisStepKind.All)`

> 步骤名的代码定义处：`Services/CmdAnalysisStep.cs`（`CmdAnalysisSteps`）
> 编排实现：`Services/CmdPartAnalysisService.cs`（`AnalyzeAndSave`）
> 一次执行 = **第 1~7 步**，共 7 件事；只有第 1 步写 CSV / JSON（不写库），其余步骤都写同一张 SQLite 表。
> 字段映射 / 判定规则的完整细节：`MSIFAITOOLS\MSIFAITOOLS\docs\CMD分析_功能概要.md`；沟通用步骤名：`CMD分析_步骤命名.md`
>
> **2026-11 变更 ③（现行口径）**：流程重排成 **7 步**，界面 **按钮号 = 步骤号**：
> `1 特注品JSON`（第 1 步，只生成 `特注品.csv` + `classify\特注品.json`，不写库）→ `2 装配图入库`（第 2 步）→
> `3 圈号拆分`（第 3 步）→ `4 要領図追加`（第 4 步）→ `5 特注登录`（第 5 步，读 `特注品.json` 写库，`特注 = 1`）→
> `6 部品コード`（第 6 步）→ `7 使い分け`（第 7 步）；另外按钮 0「前置校验」不占步骤编号（`S0P`）。
> 变更 ① 里合并出来的「第 2 步 特注品CSV+部品追加」（`SpecialProduct` / `S2`）**已再次拆成现行的第 1 步与第 5 步**
> （中间隔着第 2~4 步，因为特注登录要往装配图 / 要領図 已写好的行上加工）。
> 分步原理与逐按钮详解：`MSIFAITOOLS\MSIFAITOOLS\docs\cmd-steps\00-索引.md`。
>
> **2026-11 变更 ②**：`classify\tz.json` 改名为 **`classify\特注品.json`**（内容一直就是特注品部品表）。
> 上游 CadPartSplitter 改写新名字；本工具读 / 同步时**新名优先、读不到退回旧名 `tz.json`**，
> 升级前的目录不用重跑。数据库「数据来源」的值**仍是 `CMD分析・tz.json`**（值不变，老数据照样能被剔除）。
> 第 5 步的数据源：**`classify\特注品.json` 优先，没有 JSON 才退回 `AiAppData\*\特注品.csv`**。

## 一、前置校验

1. **防重入**：`_isRunning == true` 直接返回，防止重复点击。
2. **必须已分解**：`_classifications` 为空 → 弹「请先点击【开始分解】」并返回。
3. **输出目录**：`_lastOutputDir` 为空或目录不存在 → 弹提示并返回。
4. **取快照**：只把【分类结果】里 `PdfCategory.Assembly`（アッセンブリ図）的行复制成新列表，后台线程只读快照。
5. **没有装配图**：主按钮照常继续（第 1 步照常生成 CSV / JSON，服务层对第 2~7 步打「无需分析」后返回）；单步调用第 2~7 步时则弹「分类结果中没有『アッセンブリ図』」并返回；**第 1 步例外**（它只读 xlsx、不写库，不需要装配图行）。
6. **进入运行态**：进度条归零（Continuous）、`SetRunning(true)`、切到【日志】页。

## 二、第 1 步 · 特注品.json 作成（`S1`，不碰数据库）

7. **扫描 xlsx**：遍历 `<outputDirectory>` 的上一级（= PDF 文件夹）下 `*.xlsx`（跳过 `~$` 临时文件），文件名（去扩展名）第 5 位是 `Z` / `z` / `Ｚ` = 特注品。
8. **读部品表**：工作表 `カメラ`（没有这张表时退回第一张），按列名找 `品種 / 部品名 / 枠区分 / 部品コード / 員数 / 追加対応特注寸法`。
9. **过滤行**：`追加対応特注寸法` 写着 `追加不要 / 追加しない / 追加なし / 追加無し` 的行不写；前 5 列全空、只有特注寸法的行不算部品。
10. 生成 **`AiAppData\<文件名>\特注品.csv`** —— UTF-8 BOM + CRLF，首行固定表头；一个明细都没有也写只有表头的文件。
11. **AI 补足**（可选，配了密钥才联网）：读该図番的 `plu_table.txt`，分两次调用 —— 先补缺行 / 缺字段，再补特注寸法；Excel 已有的值一律不动。
12. 同步 **`classify\特注品.json`**（2026-11 由 `tz.json` 改名）—— 只补空白字段，对不上的 CSV 行追加成新明细（`sheet = カメラ`、`row = 0`）；文件不存在时不新建，只有旧名 `tz.json` 的目录仍写回旧名。
13. **清残留**：删掉 `AiAppData` 里没有对应特注品 xlsx 的旧 `特注品.csv`（只删这个文件名，其它文件一概不动）。

## 三、第 2 步 · 装配图部品入库（`S2`，写库）

14. **定位数据文件**：`<AiAppData>\<図番>\01_アッセンブリ図_部品機能情報.csv`（多页 PDF 第 2 页起为 `<図番>_P2`）；找不到的 PDF 记警告跳过（`MissingLtStep1File`）。
15. **建行**：按表头列名映射成部品行（`番号 / 部品名 / 枠区分 / 員数 / 切断寸法 / 部品コード` …），读不到明细的记 `NoPartData`。
16. **`xy.txt` 校验**：表里的文字能在 `xy.txt` 的坐标里对上 → 该行记「已校验」。
17. **部材名**：用「番号」在 `parts_info.json` 的 `callouts` 找圈号 → 取该圈号所在零件图的 `texts`（去数字、去 `XX部`）→ `|` 连接。
18. **特注标记**：図番（PDF 文件名）第 5 位是 `Z` → 整张表里没有「特注」的行一律记 `特注品`。
19. **清空数量**：`特注` 不是 `1` / `特注品` 的行，`数量` / `切断寸法` 一律清空。
20. **写库** `部品基本信息`（`PartBasicInfoRepository.Save`：先删该図番再插入；空「部材名」统一填 `その他`）。

## 四、第 3 步 · 圈号拆分（`S3`，写库）

21. **目标図番**：`classify\PdfInfoList.txt` 里「图面分类 = アッセンブリ図」的図番号，再补上一览里的「アッセンブリ図」。
22. **读数据**：该図番数据库里已有的行 + `parts_info.json` 的 `callouts` / `texts`（同一页只读一次）。
23. **判定拆分**：圈号必须出现在 `index` 不同、`texts` 互为包含的零件图里，才按坐标定方向（左右 / 上下）。
24. **加前缀**：部品名 / 部材名前加「右 / 左」「上 / 下」，同一部品拆成多行（番号接在已有行之后）。
25. **后处理 + 写库**：特注标记 → 清空非特注数量 → `Save` 整张覆盖写回；没拆出任何组时跳过该図番。

## 五、第 4 步 · 要領図部品追加（`S4`，写库）

26. **读清单**：`01_アッセンブリ図_要領図.csv` → 逐个要領図的 `02_要領図_部品機能情報.csv`；缺 01 / 02 文件只记日志，不影响已入库的数据。
27. **挑行**：`品種` 命中分类依据的行 + 没有 `品種` 的共通行（备注写「品種：共通」）。
28. **部材名**：按「項目」（`A部`）取对应零件图的 `texts`，拆分时加同一套位置前缀。
29. **幂等**：先剔掉上次本步写入的行（`数据来源 = CMD分析・要領図`），新行番号接在剩余行之后。
30. **同部品合并**：部品名与装配图行相同 → `区分` 取装配图行的，装配图那条删掉（同部品只留要領図 一条）。
31. **区分补全**：`区分` 还空着的行，按 部品名 → 去位置前缀部品名 → 部材名 → 去位置前缀部材名 的顺序补；同一个键上有两种以上区分视为歧义，跳过不补。
32. **写库**：特注标记 + 清空非特注数量 → `Save` 合并后的整张表（必须连同已有行一起提交，否则会冲掉第 2 步的明细）。

## 六、第 5 步 · 特注品部品登录（`S5`，写库）

33. **读分类依据**：`classify\PdfInfoList.txt` 里该図番的「判定依据」（清单里没有时退回一览的 `Evidence`）；没有依据的図番记警告跳过。
34. **读明细**：**优先读第 1 步同步出的 `classify\特注品.json`（旧名 `tz.json`）**；JSON 不存在 / 没有明细时才退回第 1 步生成的 `AiAppData\*\特注品.csv`（全部文件一起读，**不解析 Excel**），两处都读不到就记一条警告、该図番跳过。
35. **匹配品種**：`品種` 与分类依据「完全一致」（全角转半角、去空白、忽略大小写）→ 不命中再退回「包含」比较。
36. **过滤**：`部品コード` 必须含英文字母；`追加不要` 的行跳过；同 `品種 + 部品名 + 部品コード` 去重。
37. **算 H / W**：解析「追加対応特注寸法」（`2199 ≦Ｗ` 这种写法）→ H / W 上限，只给一边时另一边取默认值；`备注` 写 `品種：…；特注寸法：…`，`特注 = 1`。
38. **幂等 + 写库**：先剔掉 `数据来源 = CMD分析・tz.json` 的旧行 → 合并 `Save`；合并后为空（本次一条都不再命中）→ `ReplaceByDrawing` 把该図番清空。

## 七、第 6 步 · 部品コード正規化（`S6`，写库）

39. **读部品マスタ**：`部品マスタ\Tbl_部品マスタ.csv`（第 1 列 部品コード / 第 3 列 材質 / 第 4 列 色）。
40. **换颜色**：部品コード 里的颜色换成 `□`（`MEACC429` → `MEA□429`）。
41. **压符号**：连续符号（`□□` / `〇〇` / `△△` …）压成一个 `□`。
42. **重複チェック**：换完与同図番 / 同页码 / 同番号的另一行撞键 → 跳过并记警告（不写坏唯一索引）。
43. **写库**：`UpdatePartCodes` 只改「部品コード」一列（不建行 / 不删行）。

## 八、第 7 步 · 使い分け自動設定（`S7`，写库）

44. **分组**：同一図番内 `区分 / 参照元 / 部品コード / H下限 / H上限 / W下限 / W上限` 全同的 2 行以上 = 同一部品的多条（只有 1 行不算）。
45. **查拾い出し表**：`hiroidashiData\*.xlsx` 第 4 列（部品ｺｰﾄﾞ / 形材番号）匹配部品コード。
46. **填值**：组内按 `页码 → 番号` 排序，第 i 行取第 12 列「使い分け」的第 i 个值；值不够的行保持原样；已有「使い分け」（手工填过）不覆盖。
47. **写库**：`UpdateUsageKinds` 只改「使い分け」一列（不建行 / 不删行）。

> **顺序要求**：第 7 步必须在第 6 步之后 —— 部品コード 已统一成 `MEA□429` 这种写法，和拾い出し表一致，查表最准。

## 九、收尾

48. **解除运行态**：`SetRunning(false)`；异常 → 日志红字 + 状态栏「异常」+ 弹框后返回（已写入的数据不回滚）。
49. **汇总**：`CmdPartAnalysisService.BuildSummaryText` → 写日志 + 完成弹框 + 状态栏（有失败文件时状态栏转红），进度条按 `SavedRowCount > 0` 置满。
50. **查看结果**：在【分类结果】选中 PDF 行 →【部品信息】查看入库的部品基本信息。

## 十、执行范围（`CmdAnalysisStepKind`）

> 【CMD 分析】**主按钮** = `CmdAnalysisStepKind.All`（点一次跑完 **第 1~7 步** = 7 件事）。
> 主按钮下面一排 **8 个子按钮**各只跑一步（鼠标悬停显示该步说明）：**按钮 0 = 前置校验**、**按钮 1~7 = 第 1~7 步**。
> 其中「0 前置校验」只检查、不写库，由界面的 `Form1.RunCmdPreflight` 处理，不进服务层。

> **每个子按钮的原理详解**（逻辑 / 判定规则 / 排查表）：`MSIFAITOOLS\MSIFAITOOLS\docs\cmd-steps\00-索引.md`
> （`01-前置校验.md` … `08-使い分け.md`，一步一份）

| 子按钮（界面编号） | `CmdAnalysisStepKind` | 只跑 | 写库 |
| --- | --- | --- | --- |
| （主按钮）【CMD 分析】 | `All` | 第 1~7 步（全部；= 下面的流水账第 7–47 步） | 是（第 1 步除外） |
| 0 前置校验 | `Preflight` | 只检查：PDF 文件夹 / 分类结果 / 输出目录 / `PdfInfoList.txt` / 数据库 | 否 |
| 1 特注品JSON | `SpecialProductJson` | 第 1 步（流水账第 7–13 步） | 否（只写 CSV / JSON） |
| 2 装配图入库 | `Assembly` | 第 2 步（流水账第 14–20 步） | 是 |
| 3 圈号拆分 | `CalloutSplit` | 第 3 步（流水账第 21–25 步） | 是 |
| 4 要領図追加 | `YoryoAppend` | 第 4 步（流水账第 26–32 步） | 是 |
| 5 特注登录 | `TzParts` | 第 5 步（流水账第 33–38 步） | 是 |
| 6 部品コード | `PartCode` | 第 6 步（流水账第 39–43 步） | 是 |
| 7 使い分け | `UsageKind` | 第 7 步（流水账第 44–47 步） | 是 |

> **编号只有一套口径**：界面按钮号 = 步骤号（按钮 1 = 第 1 步 … 按钮 7 = 第 7 步），
> 日志前缀也写「第 N 步」；主按钮一次跑完的顺序 = 第 1 步 → 第 2 步 → … → 第 7 步。

- 第 3~7 步都依赖第 2 步已入库：数据库里这些図番**一行都没有** → 只记警告「请先执行 第 2 步 · 装配图部品入库」、不写库（`HasSavedRows`）。
- 第 1 步（特注品.json 作成）不写库、也不需要装配图行，因此不受上面这条限制。
- 单步执行时日志前缀仍是「【第 N 步 · 名字】」，与主按钮一致。

## 十一、产物一览

- **`AiAppData\<文件名>\特注品.csv`** —— 第 10 步生成（AI 补足见第 11 步）；第 34 步在 `classify\特注品.json` 读不到明细时才读它（兜底数据源）。
- **`classify\特注品.json`** —— 第 12 步同步（只补空白字段；第 34 步的**首选**数据源）。2026-11 由 `tz.json` 改名，读写都兼容旧名（新名优先）。
- **`<程序目录>\Data\MSIF_Parts.db`** → 表 `部品基本信息` —— 第 20 / 25 / 32 / 38 / 43 / 47 步写；
  可用 App.config 的 `PartDatabasePath` 覆盖路径。
- 想分辨某一行是哪一步写的：看「数据来源」列（`CMD分析・アッセンブリ図` / `CMD分析・要領図` /
  `CMD分析・tz.json` / `AI分析` / `手工追加`）。第 5 步（特注品部品登录）虽然读的是 `特注品.json` / `特注品.csv`，
  「数据来源」的文字**仍是 `CMD分析・tz.json`**（沿用旧值：文件虽已改名 `特注品.json`，值不变，老数据也能被正确剔除 / 覆盖）。
- 与【开始分解】的关系：本按钮**不生成** `xy.txt` / `parts_info.json` / `01_アッセンブリ図_部品機能情報.csv` 等，
  这些都来自【开始分解】（见 `docs\开始分解-步骤.md` 第 14–21 步）；缺文件时对应図番只记警告跳过。
